1. Executive Summary & Solution Architecture

The Maintenance Request System (MRS) is an enterprise-grade hybrid web application developed with ASP.NET Core 10. It combines a rich server-side MVC Razor Web Portal with a high-performance, secure RESTful Web API (v1) to automate and oversee facility repair workflows across corporate departments.

🎯 Key System Capabilities

  • Role-Based Access Control: Strict segregation of duties for Administrator, Field Technician, and Corporate Employee.
  • Automated Work Order Numbering: Generates formatted identifiers (REQ-YYYY-NNNN) uniquely tracked in SQL Server.
  • Full Audit Trail History: Chronological event logging for creations, assignments, status changes, and repair notes.

3. Security, Identity & Dual Authentication

MRS employs a unified security model that concurrently satisfies web browser sessions and distributed API consumers via hybrid authorization policies registered in Program.cs.

🔐 ASP.NET Core Identity (MVC)

Uses secure HTTP-only cookies configured with sliding expirations, Anti-Forgery Tokens (CSRF protection), and lockout protection on repetitive invalid login attempts.

  • Cookie Path: /Account/Login
  • Lockout: 5 failed attempts locks for 5 min
  • Roles: Admin, Technician, Employee
🔑 JWT Bearer Authentication (API)

Issues HMAC-SHA256 cryptographically signed tokens containing user identity, claims, and assigned role credentials for stateless mobile/client consumption.

  • Issuer: MaintenanceRequestSystem
  • Expiration: 60 minutes configurable
  • Header: Authorization: Bearer <Token>
🛡️ Multi-Tier Security Controls Matrix
Security Mechanism Implementation Detail Threat Mitigated
Rate Limiting Fixed-window limiter: 5 attempts/min on /api/v1/auth/* Brute force & Credential stuffing attacks
Resource Authorization Service checks request.EmployeeId == currentUserId Insecure Direct Object References (IDOR)
Data Sanitization DTOs omit password hashes, concurrency stamps, and internal flags Sensitive data exposure
CORS Policy Configurable allowed origins (Angular, React, Vue local ports) Unauthorized Cross-Origin requests

4. Database Schema & Domain Modeling

The database layer is managed via EF Core 10 Code-First on SQL Server 2025. It enforces referential integrity, domain constraints, soft deletion, and optimal query indexing.

🗄️ Relational Domain Schema Definition
Entity Table Key Columns & Types Relationships & Cascade Rules
ApplicationUser Id (string PK), FullName, Department, IsActive, LastLoginAt 1-to-Many with MaintenanceRequest, Comments, and Audit Histories.
MaintenanceRequest Id (int PK), RequestNumber (string UK), Title, Description, Status, Priority, CategoryId (FK), EmployeeId (FK), TechnicianId (FK) Foreign keys configured with DeleteBehavior.Restrict to prevent accidental cascaded deletion of critical audit history.
Category Id (int PK), Name, Description, IsActive Pre-seeded with Electrical, Plumbing, HVAC, IT Equipment, Furniture.
RequestComment Id (int PK), CommentText, CreatedAt, RequestId (FK), UserId (FK) Enables ongoing technical dialogue between employee and technician.
RequestHistory Id (int PK), Action, Description, CreatedAt, RequestId (FK), UserId (FK) Immutable append-only audit trail logging each status mutation and assignment.
⚡ Indexing & Soft Delete Architecture
  • Unique Business Key: IX_MaintenanceRequests_RequestNumber guarantees uniqueness for ticket lookups.
  • Soft Delete Query Optimization: Composite index on (IsDeleted, Status) enables efficient server-side filtering of active records.
  • Soft Delete Strategy: When a request is deleted, IsDeleted = true and DeletedAt = UtcNow are set, preserving historical logs without data loss.

5. Business Logic & Ticket Lifecycle State Machine

Ticket states strictly advance according to an automated finite state machine. Invalid transitions are rejected at the service layer, guaranteeing process compliance across both UI and REST API.

[Pending] ──(Admin Assigns)────────► [Assigned] │ │ │ (Admin Reject/Close) │ (Technician Starts) ▼ ▼ [Closed] ◄──(Admin/Emp Sign-off)── [Resolved] ◄──(Tech Resolves)── [InProgress]
🔄 State Transition Rules Matrix
From Status To Status Authorized Roles Validation & Business Rules
Pending Assigned Admin Assigns active Technician ID; logs TechnicianAssigned history.
Pending Closed Admin Immediate dismissal of invalid or duplicate work orders.
Assigned InProgress Technician (Assigned) Technician marks commencement of on-site inspection/work.
InProgress Resolved Technician (Assigned) Requires mandatory ResolutionNotes; stamps ResolvedAt.
Resolved Closed Admin / Employee (Author) Final verification and sign-off; stamps ClosedAt timestamp.
🛡️ Role Permission Boundaries
  • Employee: Can only update or delete requests in Pending status. Cannot reassign technicians or alter statuses.
  • Technician: Can only modify status of requests explicitly assigned to them. Cannot access admin user management.
  • Admin: Global oversight to assign technicians, configure equipment categories, and manage staff user accounts.

6. RESTful Web API Specifications (/api/v1)

The REST API delivers standardized endpoints with explicit HTTP status codes, query filtering, pagination caps, and predictable envelope responses.

📋 REST Endpoints Catalog
Method Endpoint Auth / Role Description & Behavior
POST /api/v1/auth/login Public Authenticates credentials, returns JWT token and user roles.
POST /api/v1/auth/register Public Registers new Employee/Technician account.
GET /api/v1/requests Authenticated Paginated search (?page=1&pageSize=10&priority=High&status=Pending).
POST /api/v1/requests Employee Creates new ticket. EmployeeId extracted securely from JWT claims.
GET /api/v1/requests/{id} Resource Allowed Returns full details, category, employee, technician, comments, history.
POST /api/v1/requests/{id}/assign Admin Assigns a technician to the request and sets status to Assigned.
PUT /api/v1/requests/{id}/status Technician / Admin Transitions request status and attaches resolution notes.
GET /api/v1/requests/{id}/comments Resource Allowed Fetches chronological technical comments for a work order.
GET /api/v1/dashboard/admin Admin Aggregated metrics: requests by status, priority, category.
